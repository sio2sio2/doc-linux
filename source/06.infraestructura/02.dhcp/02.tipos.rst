.. _DHCP-clients:

Clientes
========
En *Linux* se usan, fundamentalmente, tres clientes:

.. _dhclient:
.. index:: dhclient

:program:`dhclient` (ya obsoleto)
   Es el cliente del |ISC| y hasta no hace tanto el más habitual en las distribuciones.
   Su uso es bastante sencillo:

   * Para pedir configuración para la interfaz *eth0*::

      # dhclient -v eth0

   * Para desconfigurar la interfaz *eth0*, advirtiendo al servidor::

      # dhclient -r eth0

     Si no se quiere avisar al servidor (con lo cual no se liberará la |IP|),
     debe usarse la opción :kbd:`-x`

   Este cliente revisa el fichero :file:`/etc/dhcp/dhclient.conf` dentro del
   cual puede manipularse la forma en que se pide la configuración al servidor.

.. _dhcpcd:
.. index:: dhcpcd

:program:`dhcpcd`
   Es el sustituto natural del anterior (en *Debian* a partir de *Trixie*) y
   bastante más completo y más flexible.  Almacena su configuración en
   :file:`/etc/dhcpcd.conf` y en ese archivo, entre otras cosas, permite
   especificar incluso configuraciones estáticas para interfaces o qué
   interfaces no queremos configurar a través de la aplicación.  Esto es debido
   a que puede usarse de dos maneras\ [#]_:

   a. Gestionado de forma manual las interfaces al estilo de como lo hace
      :command:`dhclient`.
   #. Como demonio, lo que determina que cobre sentido lo que acabamos de decir
      acerca del archivo de configuración. Por ejemplo:

      .. code-block:: ini

         noipv6  # No nos interesa IPv6.

         denyinterfaces eth2  # No queremos hacernos cargo de eth2
         #allowinterfaces eth0 eth1  # Es una alternativa.

         # eth0 no requiere bloque, ya que se configura de forma predeterminada.

         # Configuración estática de eth1
         interface eth1
            static ip_address=192.168.255.2/24
            static routers=192.168.255.1
            static domain_name_servers=1.1.1.1 8.8.8.8

      Con esta configuración\ [#]_, podemos configurar las interfaces manipulando el
      servicio asociado:

      .. code-block:: console

           # systemctl restart dhcpcd

      En cualquier caso, *Debian* no tiene habilitado el servicio (ya que todo
      se gestiona con :program:`ifupdown`), por lo que tendríamos que gestionar
      manualmente las interfaces.

   Cuando no se usa como demonio, se utiliza de modo semejante a
   :command:`dhclient`:

   .. code-block:: console

      # dhcpcd -b eth0 eth1  # Podemos gestionar varias. -b para segundo plano.
      # dhcpcd eth2          # Rehusará hacer nada con eth2.

   Aun usándose de forma manual, el archivo de configuración sigue siendo válido
   y, por tanto, *eth0* se configurará dinámicamente, *eth1* recibirá una
   asignación estática, y *eth2* no se configurará en absoluto.

   Para liberar las interfaces y desconfigurarlas:

   .. code-block:: console

      # dhcpcd -k eth0 eth1

   que provocará que para *eth0* se notifique al servidor la liberación
   (paquete *DHCPRELEASE*).

   .. note:: A diferencia de :program:`dhclient`, por defecto, las configuraciones dinámicas
      soportan la técnica `IPv4ALL o Zeroconf <https://es.wikipedia.org/wiki/Zeroconf>`_
      lo que determina que cuando no existe servidor |DHCP|, la interfaz se
      autoconfigura escogiendo una dirección |IP| de la red ``169.254.0.0/16``.
      Este comportamiento, no obstante, puede alterarse añadiendo:

      .. code-block:: ini

         noipv4ll

      a la configuración global o a la configuración particular de una interfaz.

.. _udhcpc:

:program:`udhcpc`
   Es el microcliente del proyecto `busybox <https://www.busybox.net/>`_ y que
   suelen usar las distribuciones mínimas como SliTaZ_, Alpine_ o linux
   empotrados. Su uso básico es el siguiente:

   * Para pedir configuración para la interfaz *eth0*::

      # udhcpc -b -R -p /var/run/udhcpc.eth0.pid -i eth0 -x hostname:nombre_maquina

     donde :kbd:`-x` sirve para pedir opciones de configuración al servidor. En
     el ejemplo, se le ha sugerido que nos adjudique un nombre de máquina
     (:kbd:`hostname`), pero puede sugerirse otras como un tiempo de concesión
     (:kbd:`lease`). Para sugerior varias debe repetirse el argumento.

   * Para desconfigurar la interfaz y parar el cliente::

      # kill -USR2 $(cat /var/run/udhcpc.eth0.pid)
      # kill -TERM $(cat /var/run/udhcpc.eth0.pid)

Servidores
==========
Tipos
-----
Un servidor |DHCP| puede trabajar de tres formas distintas:

#. Como servidor |DHCP| en sí proporcionando la información de red a los
   clientes que lo solicitan y que es la función a la que dedicamos el tema.

#. Como |DHCP| *relay*, en que el servidor se limita a retransmitir los paquetes
   enviados por el servidor |DHCP| real. Se usa para resolver el caso en que el
   servidor |DHCP| no comparte red con los cientes:

   .. image:: files/DHCPrelay.png

   En este caso, el *router*, además de comunicar ambas redes, retransmite hacia
   el servidor las peticiones de los clientes y retransmite a los clientes las
   respuestas del servidor.

#. Como *proxy* |DHCP|, que se limita a complementar la información del servidor
   |DHCP| real, comunicando a los clientes la información adicional para el
   arranque por red. Trataremos este tipo de servidor al tratar el
   :ref:`servicio PXE <pxe>`.

Implementaciones
----------------
Las implementaciones libres de servidores |DHCP| más usadas son las siguientes:

`udhcpd <https://udhcp.busybox.net/>`_
   Es el microservidor del proyecto `busybox <https://www.busybox.net/>`_ y suele
   encontrarse en los linux empotrados en algunos dispositivos.

`dnsmasq <http://www.thekelleys.org.uk/dnsmasq/doc.html>`_
   Es un servidor ligero que incorpora, además, un |DNS| y un |TFTP|. Es más que
   competente para la resolución de la mayor parte de las situaciones con que
   nos encontramos en pequeñas redes locales.

`ISC DHP Server <https://www.isc.org/dhcp-manual-pages/>`_
   Es el servidor tradicional del |ISC| (que también patrocina el servidor |DNS|
   :program:`bind`). Es bastante más pesado que el anterior, pero permite un
   mayor control sobre la configuración.

`ISC KEA <https://kea.isc.org/wiki>`_
   Es el nuevo servidor del |ISC|, que previsiblemente sustituirá al anterior en
   el futuro.


.. rubric:: Notas al pie

.. [#] En *Debian* la gestión de las interfaces corre a cargo de la aplicación
   :program:`ifupdown`, por lo que el uso como demonio de este cliente entra en
   conflicto. Por ese motivo, el cliente está desdoblado en dos paquetes:
   :deb:`dhcpcd-base`, que contiene el cliente en sí, y :deb:`dhcpcd` que
   contiene los archivos necesarios para correrlo como demonio. Por defecto,
   sólo está instalado el primero.

.. [#] En la configuración hemos identificado las interfaces que no queremos
   configurar (:code:`denyinterfaces eth2`), lo cual no es exactamente
   equivalente a que declaremos qué interfaces queremos configurar
   (:code:`allowinterfaces eth0 eth1`). Esto es así, porque ante una nueva
   interfaz *eth3*, en el primer caso :program:`dhcpcd` se encargaría de su
   gestión (dinámica como *eth0*), mientras que en el segundo, no.
